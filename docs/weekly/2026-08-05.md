## 分块策略对比

做这个好处是：**chunk 策略影响检索质量**，是经典调参点。提升evidence_hit

检索的依据是evidence_hit

最开始我将chunk size设为500，800,1000，1500到2000，

| PDF | 页数 | 总字数 | 单页最长（字） |
|---|---|---|---|
| 消费者权益保护法 | 16 | 8312 | 681 |
| 产品质量法 | 18 | 8720 | 587 |
| 反不正当竞争法 | 13 | 6243 | 562 |
| 广告法 | 24 | 11476 | 567 |
| 电子商务法 | 22 | 10653 | 574 |
| 食品安全法 | 63 | 31960 | 605 |
| **合计** | **156** | **77,364** | **最长段落 680** |



其次我们切分的工具首先是用`分隔符`切分，其次再是`chunk size`的长度大小。所以只有chunk size等于500的时候切分成了250块,其他时候都是156块,即一页为一块，PDF本身就是天然块。

如果换`<680的chunk size`会更好一些吗？比如300,400,500，我也进行了实验但是实验证明数据并不如。因为在实验过程中有完整的法律条文被切断了，所以检索不到了。

结果：

| chunk_size:overlap | 文本段数 | 证据命中 | 说明 |
|---|---|---|---|
| 500:100 | 250 | 25/33 **(75.8%)** | 唯一触发切分 → 法条被腰斩，反而更差 |
| 800:160 | 156 | 26/33 **(78.8%)** | 每页一块 |
| 1000:200（生产默认） | 156 | 26/33 (78.8%) | 每页一块 |
| 1500:300 | 156 | 26/33 (78.8%) | 每页一块 |
| 2000:400 | 156 | 26/33 (78.8%) | 每页一块 |
| 1000:0 / 1000:100 / 1000:300 | 156 | 26/33 (78.8%) | 每页一块 |

**结论**：chunk_size ≥ 680 不触发切分，全部 = 每页一块 = 156 段（逐字节一致）；
唯一触发切分的 500 反而更差——物理行切分腰斩完整法条；
该语料下 chunk_size 不是检索质量的杠杆，7 道失败题是短锚句召回缺口，指向混合检索。

*失败题的证据锚句就在完整块里、就在正确页码上*，却进不了 Top-5。块已经是"完整法条"了，还能怎么优化块？——块不是瓶颈，**召回才是**。**短锚句（"销售者赔偿后……"这种 10~17 字的句子）在向量检索里词面匹配弱**，这是*检索侧的经典弱点*，跟 chunk_size 无关。

**overlap 只在切分发生时才有意义**——它决定相邻两块之间共享多少字。切分没发生 → 每页一块 → 没有"相邻块"可以重叠 → overlap 完全空转。

## WSL 部署·第 1 课：装 Ollama（2026-08-05 晚）

目标：把空白 WSL Ubuntu 变成能跑项目的环境，第一步装嵌入服务 Ollama。
成果：ollama --version = 0.32.5，装好了。

### 踩坑记录（按顺序，这是最有价值的部分）

1. 忘记 sudo 密码
   - WSL 特性：Windows 侧可以绕过密码直接进 root（这是 WSL 自带的，面试能讲）
   - 在 PowerShell 跑：wsl -d Ubuntu -u root，然后 passwd an 重置密码
   - 注意：Linux 输密码不显示任何字符，这是正常的

2. Ollama 安装报错缺 zstd
   - 报错信息本身就写了怎么治：sudo apt-get install zstd
   - 装软件通用动作：sudo apt-get update && sudo apt-get install -y 包名
   - 结论：Linux 下报错是说明书，先读报错

3. 下载巨慢（估计要 2.5 小时）
   - 根因：WSL 不走 Windows 的代理。Windows 侧代理只对 Windows 生效，WSL 是另一套系统，不经过它直连所以慢
   - 配代理的完整链路见下一条

4. 给 WSL 配代理（完整排障链路）
   - 查 Windows 真实 IP：ip route show default，看 default via 后面的 IP（<Windows-IP>）
     - 坑：resolv.conf 里的 <DNS网关IP> 只是 DNS 网关，不监听代理端口
   - 代理软件开 Allow LAN（允许局域网连接），并且必须完全退出重开才生效
   - 验证监听：netstat -ano | findstr :<端口>，Local Address 必须变成 0.0.0.0:<端口>
     - 127.0.0.1 = 只监听本机，其他机器连不进
   - 防火墙放行（管理员 PowerShell）：
     New-NetFirewallRule -DisplayName "WSL proxy" -Direction Inbound -LocalPort <端口> -Protocol TCP -Action Allow
   - 写进 ~/.bashrc 持久化，每次启动自动生效：
     export hostip=$(ip route show default | awk '{print $3}')
     export http_proxy="http://$hostip:<端口>"
     export https_proxy="http://$hostip:<端口>"
   - 用动态查 IP 而不是写死：WSL 重启后 NAT 网卡 IP 可能变，写死会失效

### 命令速查表（不用背，存着查）
| 命令 | 干什么 |
| --- | --- |
| curl -I URL | 看 URL 通不通（网络诊断第一步） |
| curl -fsSL URL \| sh | 下载脚本并执行 |
| sudo apt-get update && sudo apt-get install -y 包名 | 装软件 |
| systemctl status 服务名 | 看后台服务状态 |
| wsl -d Ubuntu -u root | 以 root 进 Ubuntu（忘密码的救命招） |
| passwd 用户名 | 改密码 |
| ip route show default | 查网关（Windows 主机 IP） |
| netstat -ano \| findstr :端口 | 看谁在监听某端口 |
| source ~/.bashrc | 让刚改的配置立即生效 |
