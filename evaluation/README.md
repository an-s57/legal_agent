# 法律 RAG 检索评测与调优记录

> 最后更新：2026-07-27
> 本文既说明评测如何运行，也记录当前可复核的实验结论。每次运行的完整原始结果保存在 [`results/`](./results/) 目录。

## 1. 评测目标与边界

本评测只回答一个问题：在固定的法律语料、Embedding、切分方式和 Reranker 配置下，FAISS 应先召回多少条候选文本，以及最终应向 LLM 提供多少条重排结果，才能让正确法律依据稳定出现。

它**不**用于评估：

- Agent 是否正确选择联网搜索工具；
- 最终 LLM 回答是否通顺、完整或适用于真实案件；
- 法律建议的现实正确性、时效性或执业合规性。

## 2. 语料、题集与指标

### 语料边界

题集只使用当前 FAISS 已实际入库的 5 部法律文件，共 110 个文本块：

| 法律文件 | 题数 |
| --- | ---: |
| 《消费者权益保护法》 | 12 |
| 《产品质量法》 | 10 |
| 《反不正当竞争法》 | 10 |
| 《广告法》 | 8 |
| 《食品安全法》 | 10 |

《电子商务法》PDF 当前无法被 PDFPlumber 正常提取，未进入 FAISS；旧题集中的电商法题不参与本轮调优。法律语料更新、切分方式变化或模型变更后，应重新核验题目并重跑评测。

### 题集与数据划分

[`retrieval_k_tuning_50.json`](./retrieval_k_tuning_50.json) 包含 50 道人工标注的用户式法律检索题：

- 开发集：33 题，用于选择 `K` 和 `Top-K`；
- 验证集：17 题，用于确认选定配置；
- 每题包含目标来源、目标条款、PDF 页码和关键证据提示。

验证集此前曾参与 K=20/30 的确认，因此本报告将其称为“验证确认”，而不是完全未见过的最终测试集。后续若要形成更严格的最终结论，应额外保留一批从未用于选参的新题。

### 指标说明

- **来源命中率**：最终返回的文本中是否包含标注的正确法律文件。
- **严格证据命中率**：最终返回的文本中是否同时匹配正确来源、PDF 页码和关键法条片段。
- **Rerank 回退**：重排序异常后是否退回 FAISS 原始结果。
- **P95 耗时**：95% 的题目可在该时间以内完成；用于观察最慢的一小部分请求。
- **累计检索时间**：由平均单题检索时间乘以题目数估算，不包含模型加载、预热和终端输出等固定开销。

## 3. 实验设置

```text
PDF → 文本切分 → nomic-embed-text → FAISS 粗召回 →
BAAI/bge-reranker-base 重排序 → 返回最终 Top-K
```

- Embedding：`nomic-embed-text`（本地 Ollama）；
- 向量库：FAISS；
- 重排序：`BAAI/bge-reranker-base`；
- 运行环境：本地 CPU；每轮实验预加载并预热 FAISS、Embedding 与 Reranker；
- 计时范围：向量检索 + 重排序，不包含前端、FastAPI、Planner、联网搜索、远程 LLM 生成与案情摘要更新。

## 4. K 参数调优（开发集，33 题）

固定 `Top-K=5`，比较 FAISS 粗召回数量 `K`。首次扫描于 2026-07-26 21:42 完成；K=30 补充实验于 21:48 完成；K=32、35 边界验证于 2026-07-27 14:30 完成。

| K | 来源命中率 | 严格证据命中率 | 平均向量检索 | 平均重排序 | 单题总检索（平均 / 中位数 / P95） | 33 题累计检索时间 | 回退 |
|---:|---:|---:|---:|---:|---:|---:|---:|
| 5 | 30/33（90.9%） | 8/33（24.2%） | 0.41s | 1.35s | 1.76s / 1.47s / 2.90s | 58.0s | 0 |
| 10 | 31/33（93.9%） | 16/33（48.5%） | 0.38s | 2.50s | 2.89s / 2.75s / 4.91s | 95.2s | 0 |
| 15 | 31/33（93.9%） | 20/33（60.6%） | 0.35s | 3.57s | 3.91s / 3.87s / 4.64s | 129.2s | 0 |
| 20 | 31/33（93.9%） | 23/33（69.7%） | 0.34s | 4.60s | 4.94s / 4.86s / 5.63s | 163.1s | 0 |
| 30 | 32/33（97.0%） | 26/33（78.8%） | 0.42s | 8.91s | 9.34s / 8.50s / 12.30s | 308.1s | 0 |
| 32 | 32/33（97.0%） | 26/33（78.8%） | 0.57s | 11.48s | 12.05s / 12.82s / 13.79s | 397.5s | 0 |

结论：K 从 20 提升至 30 后，严格证据命中率从 **69.7%** 提升至 **78.8%**；K=32、35 未带来额外命中。因此选择候选数量更少的 **K=30**。K=35 的一次耗时低于 K=32，属于本地 CPU 负载波动，不能据此认为更大的 K 更快。

## 5. Top-K 参数调优（开发集，33 题）

固定 `K=30`，于 2026-07-27 14:44 至 15:00 分别比较最终返回给 LLM 的 `Top-K=3、5、7`。

| Top-K | 来源命中率 | 严格证据命中率 | 平均向量检索 | 平均重排序 | 单题总检索（平均 / 中位数 / P95） | 33 题累计检索时间 | 回退 |
|---:|---:|---:|---:|---:|---:|---:|---:|
| 3 | 32/33（97.0%） | 25/33（75.8%） | 0.35s | 6.58s | 6.93s / 6.73s / 7.95s | 228.8s | 0 |
| 5 | 32/33（97.0%） | 26/33（78.8%） | 0.37s | 6.85s | 7.22s / 6.67s / 11.62s | 238.4s | 0 |
| 7 | 32/33（97.0%） | 26/33（78.8%） | 0.50s | 9.79s | 10.29s / 11.69s / 13.07s | 339.6s | 0 |

结论：Top-K=3 比 Top-K=5 少命中 1 道精确证据；Top-K=7 没有带来额外命中。因此选择 **Top-K=5**。Reranker 无论最终返回 3、5、7 条，都会先对 30 条候选文本打分；表中的耗时差异受本地 CPU 负载影响，不能单独归因于 Top-K。

## 7. 当前线上配置与限制

线上法律检索工具当前明确使用：

```text
FAISS 粗召回 K = 30
Reranker 最终返回 Top-K = 5
```

当前结论仅适用于这 5 份本地法律文件和本题集；严格证据命中不等同于最终 LLM 回答一定正确、完整或合规。知识库、切分策略、Embedding 或 Reranker 模型改变后，应重新运行本评测。

## 8. 实际运行

运行前：

1. 在项目根目录使用 `.venv`；
2. 确保 Ollama 正在运行，并已拉取 `nomic-embed-text`；
3. 不需要启动 `main.py`，因为 `--retrieval-only` 不会调用 FastAPI、Agent、联网工具或远程 LLM。

先用 3 题确认环境正常：

```powershell
& .\.venv\Scripts\python.exe .\evaluation\evaluate.py `
  --retrieval-only `
  --questions .\evaluation\retrieval_k_tuning_50.json `
  --split development `
  --limit 3 `
  --k-values 20 `
  --top-k 5
```

例如，固定 K=30 后测试不同 Top-K：

```powershell
& .\.venv\Scripts\python.exe .\evaluation\evaluate.py `
  --retrieval-only `
  --questions .\evaluation\retrieval_k_tuning_50.json `
  --split development `
  --k-values 30 `
  --top-k 5
```

结果会自动保存到 `evaluation/results/`，包含每题命中情况、候选数、回退状态和平均/中位数/P95 耗时。

## 10. 联网搜索服务对比与生产接入（历史 DuckDuckGo 基线 / ddgs / AnySearch）

本项目的本地 RAG 评测与联网搜索服务评测是两件不同的事。前者评估 `FAISS → Reranker` 是否找对本地法条；后者比较网页搜索接入能否更稳定地找到**官方**法律法规与办事渠道，二者都不直接代表最终法律建议正确。

其中 `duckduckgo-search` 是历史旧接入，已提示改名为 `ddgs`；本轮保留它作为基线，同时在**独立评测脚本**中加入新版 `ddgs`，以避免把“旧 Python 包的问题”误判为 DuckDuckGo 搜索本身的问题。2026-07-28 起，线上 `tools/legal_tools.py` 已采用 **AnySearch 主搜索 + ddgs 失败兜底**。

题集 [`web_search_benchmark_20.json`](./web_search_benchmark_20.json) 包含 20 道人工标注题，覆盖精确法条、官方办事流程、时效性政策和口语化维权。每题预先标注：

- 可接受的官方域名；
- 用于判断搜索主题是否正确的核心关键词组；
- 用于观察法条编号、金额、地域等信息是否已经出现在摘要中的细节关键词组。

脚本 [`web_search_benchmark.py`](./web_search_benchmark.py) 会让历史 `duckduckgo-search` 接入、新版 `ddgs` 与 AnySearch 使用相同查询、相同 `Top-3` 数量，并自动记录成功率、官方来源命中@3、核心主题命中@3、两者同时命中的自动通过率、细节摘要覆盖率，以及平均/中位数/P95 耗时。

搜索摘要通常只显示法律全文的开头，因此“第五十五条”等深处条文未出现在摘要中，不应直接判定搜索失败；条文编号等细节只作为诊断数据。该评测脚本不会调用 FastAPI、Agent、LLM、FAISS 或 Reranker；运行脚本本身也不会改动生产中的 `web_legal_search` 配置。

运行前在项目根目录 `.env` 中配置（不要提交或分享密钥）：

```text
ANYSEARCH_API_KEY=你的AnySearch密钥
```

先做 3 题冒烟测试：

```powershell
& .\.venv\Scripts\python.exe .\evaluation\web_search_benchmark.py --limit 3
```

确认无认证或网络错误后，先只让两个可用候选跑完整 20 题：

```powershell
& .\.venv\Scripts\python.exe .\evaluation\web_search_benchmark.py --providers ddgs anysearch
```

默认命令会运行三个候选；若只想排查一个服务，可用 `--providers duckduckgo`、`--providers ddgs` 或 `--providers anysearch`。每次结果会写入 `evaluation/results/`：一份 JSON 保留完整 Top-3 原始链接和指标，一份 Markdown 汇总结果。Markdown 最多只列出 6 道自动评分有分歧或双方都失败的题，供人工抽查；不需要人工逐条判断全部结果。

### 2026-07-27 正式对比结果（20 题）

在相同 20 道题、相同查询后缀 `法律法规 中国`、相同 Top-3 数量下，对新版 `ddgs` 与 AnySearch 进行对比。原始结果见 [`web_search_benchmark_20260727_214249.json`](./results/web_search_benchmark_20260727_214249.json)，自动生成的摘要见 [对应 Markdown 报告](./results/web_search_benchmark_20260727_214249.md)。

| 服务 | 成功返回 | 官方来源命中@3 | 核心主题命中@3 | 自动通过@3 | 细节摘要覆盖（平均） | 平均 / 中位数 / P95 耗时 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| DuckDuckGo（ddgs） | 20/20（100.0%） | 9/20（45.0%） | 16/20（80.0%） | 8/20（40.0%） | 82.5% | 4.24 / 4.06 / 5.43 s |
| AnySearch | 20/20（100.0%） | 19/20（95.0%） | 20/20（100.0%） | 19/20（95.0%） | 57.5% | 1.52 / 1.49 / 2.21 s |

指标含义：

- **成功返回**：请求未发生异常，且服务至少返回一条结果；它不只是“没有超时”，空结果同样记为失败。
- **官方来源命中@3**：Top-3 中至少有一条 URL 属于该题预先标注的官方域名，例如 `gov.cn`、国家法律法规数据库、法院或人社部门网站。
- **核心主题命中@3**：Top-3 的标题或摘要至少覆盖该题的核心法律名称、办事渠道或纠纷主题。
- **自动通过@3**：同时满足“官方来源命中@3”和“核心主题命中@3”；它是联网搜索质量的可复核代理指标，不等同于最终法律意见正确。

结论：在本题集和本地网络环境中，AnySearch 的自动通过率为 **95.0%**，高于 `ddgs` 的 **40.0%**；平均网页搜索耗时比 `ddgs` 低约 **64%**。因此已选择 **AnySearch 作为生产主搜索服务**，并使用 `ddgs` 作为失败兜底。

同时保留一个明确限制：口语化题“买到假鞋商家不理我怎么投诉”中，AnySearch 返回了第三方维权内容，未命中预期的 12315/市场监管官方渠道。后续接入时应评估“官方渠道”查询改写或来源过滤；不能因为总体指标较高而忽略这类失败案例。

接入后已完成三项最小验证：AnySearch 主服务直连成功、使用无效密钥时 `ddgs` 回退成功、前端 SSE 链路可完成一次联网问答。该结果证明主备切换路径可用，但不代表所有口语化查询均已达到官方来源要求。
